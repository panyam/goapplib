# docsite/

The s3gen site at https://panyam.github.io/goapplib/, its own Go module. `README.md` here has the commands, the layout, and the steps for adding a page or a demo.

- `make exercise-docsite` (mission #91, from the repo root) builds the site, runs its Go tests (templates parse, nav wired, internal links resolve), then loads every page and runs every live demo in headless Chromium (`run.mjs`). `.github/workflows/docs.yml` runs it on every PR and deploys `dist/` from `main`. Checks waiting on a ticket sit in `pending` in `run.mjs`, with XPASS as in `exercise/`.
- A demo is `demos/<name>/`, embedded with `{{ demo "<name>" }}`, and calls `ready()` or `failed()` from `demos/_lib/frame.ts`. A demo with `wasm/` gets its Go built to wasm beside the wasmhost worker. A demo with `page/` is an island page that `internal/islanddemo` renders at build time, since Pages can't run a server.
- The Go API reference (`content/reference/api.md`) is generated by `apiref.go`, and a test fails when an exported name is missing. Whole-app guide code lives in `examples/<name>/` and is included with `includeFileText`, so it compiles.
- `make demos` writes `static/`, and only `make build` copies it into `dist/`, which `run.mjs` serves. A demo checked with `make demos` alone is checked against the old bundle.
- `build.mjs`'s `one-copy` plugin resolves `@panyam/tsappkit`, solid-js, Connect and `dockview-core` from here, so a demo importing another package's source still bundles one copy of each.
- The dock demo (`demos/dock/`, #141) fetches site pages and moves their article into panels. It resolves the article's relative `href`/`src` against the page's own URL (they'd otherwise resolve against the demo frame and navigate it away), and it strips its own figure from a fetched dock guide so it doesn't open inside itself. Under automation (`navigator.webdriver`) it checks drawer geometry and stacking before calling `ready()`.
- The dock lab (`content/guide/dock-lab.md`, demos `dock-pinned` and `dock-popout`, fixtures in `demos/_dock/`) answers questions in a results table in the reader's browser, and runs itself under automation. Any extra `.html` in a demo's directory ships beside it (the popout demo's `popout.html`). `frame.ts` ignores "ResizeObserver loop" errors, which dockview raises while windows open and close.
- `go build` here needs `-buildvcs=false` in a worktree; the Makefile sets `GOFLAGS` to it.
