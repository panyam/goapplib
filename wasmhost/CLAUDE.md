# wasmhost/

Go handlers running as wasm in a Web Worker; the client side is tsappkit's `wasmhost` entry point. The guides are https://panyam.github.io/goapplib/guide/wasmhost/ and `.../guide/wasmhost-state/`.

- **Exports never block.** Every `<ns>.*` export copies its arguments and returns a Promise, doing the work on a goroutine (`promise()` in `js.go`). Work run inside the `js.FuncOf` callback hangs as soon as a handler waits on JS, and it hangs rather than failing, which is why `wasm-test` has `-timeout 60s`.
- **Streaming out of a busy worker works; reaching into one doesn't.** A handler's `Flush` reaches the page mid-loop, but nothing posted to the worker (a second request, a cancel) is seen until the handler yields or returns. A lane's abort terminates the worker for that reason, and `oneShotFetch` and lanes keep a worker until its streamed body ends (`untilBodyEnds`).
- **Worker and client ship together.** A page from one tsappkit version must load that version's `wasmhost/worker.js`. The v0.2.0 worker treats an unknown request kind as `unmount`.
- **`make wasm-test` runs under `env -i`.** `wasm_exec_node.js` copies the environment into the wasm and refuses one over its limit (`total length of command line and environment variables exceeds limit`), and a 7.5 KB shell is already over. Running `GOOS=js go test` by hand needs the same (#118).
- **Wasm tests under Node.** Await each JS Promise as soon as it's created. Node ends the process on a rejection with no handler yet.
- **Pick the piece by the problem.** Rebuildable state across a reload: `Cache` (`BrowserCache`), keyed by `CacheKey` of the inputs. A big transient peak: `oneShotFetch`, leaving its result in the cache. Quick requests behind long ones, or aborting a job that never yields: `startLane` per kind of request. A long-lived worker creeping up: `maxMemoryBytes` on its lane with a restore-only `warm`, plus `restartIf` on `heap.heapAlloc`, always with `maxMemoryBytes` (the live heap needs a collection, and `restartIf` alone collects at every idle moment, #121). `exercise/workerstate/` uses all of them.
- **Measure before choosing.** `oneShotFetch` only pays when the peak dwarfs the live state, and each lane holds its own copy of the state (agni went from about 455 MB to 800–889 MB with two lanes). `GOMEMLIMIT` and low GOGC raised agni's wasm peak (agni#988), so the guide recommends neither without a measurement. agni#991 has the Jetson numbers behind `restartIf`'s 0.55 ratio.
